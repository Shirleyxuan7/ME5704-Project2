# Working together on this repository

All four of us work on the whole code base. The rules below keep `main` always working.

## One-time setup

```bash
git clone https://github.com/<owner>/<repo>.git
cd <repo>
pip install -r requirements.txt
pytest -q            # should print "39 passed"
```

## Everyday workflow

1. **Update first:** `git checkout main` then `git pull`.
2. **Create a branch** for one piece of work, named after what it does:
   `git checkout -b fix-flux-near-source` (or `report-figures`, `add-boole-rule`, ...).
3. **Make small commits** with clear messages in English:
   `git commit -m "Use one-sided differences next to the source"`.
4. **Check before pushing:** `pytest -q` passes and `python main.py --fast` runs.
5. **Push and open a Pull Request:** `git push -u origin <branch>`, then click
   *Compare & pull request* on GitHub. Describe what changed and why.
6. **Review:** at least one other teammate reads the PR (and the automatic test run must be green)
   before it is merged into `main`.
7. After merging, everyone runs `git pull` on `main`.

## Conventions

* Comments, docstrings, commit messages and PR descriptions are in English.
* Index convention: `T[i, j]` with x = i*h, y = j*h.
* Every new numerical method gets a test with a known answer in `tests/`.
* Change problem data only in `heatplate/config.py`.
* `results/` is regenerated by `python main.py`; commit it only when the numbers in the report change.
* Discuss before changing a modelling assumption (README, section 3): it changes every result.
